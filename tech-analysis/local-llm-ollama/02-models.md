# 02. 모델 상세와 선정 근거

> 설치한 3개 모델의 상세, 벤치마크 기반 선정 근거, 그리고 검토했지만 설치하지 않은 후보와 그 이유를 기록한다. 설치/구동 절차는 [01-install.md](01-install.md), 전체 요약은 [overview.md](overview.md) 참고.

> ⚠️ **벤치마크 신뢰도 주의**: 이 문서의 수치들은 대부분 벤더 발표/2차 출처(2026년 5월 기준)에서 가져온 **참고용(indicative)** 값이다. 독립 검증된 수치가 아니므로 절대값보다 모델 간 상대 비교 정도로 받아들일 것.

## 선정의 출발점: 3개 용도 슬롯

| 슬롯 | 용도 |
|---|---|
| 1. 코딩 | 코드 작성/리뷰/설계/자료분석 |
| 2. 추론(reasoning) | 다단계 추론 중심 작업 |
| 3. 한국어·일반 | 한국어 글쓰기, 주식·취미 등 일상 질의 |

리서치 에이전트 2개가 M4 Pro 48GB 제약과 2026년 5월 기준 벤치마크로 후보를 분석했고, 슬롯별 최종 결정은 아래와 같다.

---

## 설치한 모델 (3종)

### 1. `qwen3.6:27b` — 코딩(품질) / 추론 겸용

| 항목 | 값 |
|---|---|
| 유형 | dense 27B |
| context | 256K |
| 용도 | 코드리뷰·설계·자료분석, thinking 모드 추론 |
| 크기(list) | 17GB |
| ID | a50eda8ed977 |
| 출시 | 약 2026-04-22 |

벤치마크(참고용):

| 벤치마크 | 점수 |
|---|---|
| SWE-bench Verified | 77.2 |
| SWE-bench Pro | 53.5 |
| LiveCodeBench v6 | 83.9 |
| Terminal-Bench 2.0 | 59.3 |
| AIME 2026 | 94.1 |
| MMLU-Pro | 86.2 |
| GPQA-Diamond | 87.8 |

> 📌 이전 플래그십 및 구형 `qwen3-coder` 후보를 코딩에서 모두 앞선다. thinking 모드를 내장해 **별도 추론 전용 모델 없이도 reasoning 슬롯을 흡수**한다(아래 deepseek-r1 미설치 사유 참조).

> ⚠️ 현재 Ollama에서 이 모델의 **vision/이미지 입력 경로가 깨져 있다**. 텍스트/코딩 작업은 정상이지만 이미지 첨부는 동작하지 않는다.

### 2. `qwen3-coder:30b-a3b-q4_K_M` — 코딩(속도)

| 항목 | 값 |
|---|---|
| 유형 | MoE, 총 ~30.5B / 활성 ~3.3B |
| 양자화 | Q4_K_M |
| context | 256K |
| 용도 | 빠른 인터랙티브 코딩 |
| 크기(list) | 18GB (런타임 ~21GB) |
| ID | 06c1097efce0 |

벤치마크(참고용): SWE-bench 약 70 (구세대). 강점은 절대 정확도가 아니라 **속도/에이전틱 처리량(throughput)**이다.

> 📌 활성 파라미터가 ~3.3B로 작아 토큰 생성이 빠르다. 다만 MoE라도 전체 파라미터(~30.5B)는 메모리에 상주해야 한다. smoke test에서 "OK" 응답을 약 6.5초에 반환, `ollama ps`에서 100% GPU·런타임 21GB·context 32768로 확인됨([01-install.md](01-install.md) 3절).

**코딩 슬롯을 2종으로 둔 이유**: 무거운 리뷰/설계/자료분석은 품질이 높은 dense `qwen3.6:27b`로, 빠른 반복이 필요한 인터랙티브 코딩은 MoE `qwen3-coder:30b`로 역할을 분담한다. 48GB에서 둘이 동시 상주는 불가하므로 hot-swap으로 전환한다.

### 3. `gemma3:27b-it-qat` — 한국어·일반

| 항목 | 값 |
|---|---|
| 유형 | dense 27B, instruction-tuned |
| 양자화 | QAT (양자화 인식 학습) |
| context | 128K |
| 용도 | 한국어 글쓰기·일반(주식·취미 등), 멀티모달 |
| 크기(list) | 18GB |
| ID | 29eb0b9aeda3 |

벤치마크(참고용):

| 벤치마크 | 점수 |
|---|---|
| KMMLU-Pro | 50.7 |
| KMMLU-Redux | 53.3 |
| context | 128K |

> 📌 **QAT(Quantization-Aware Training)** 모델이다. 일반적인 사후 양자화(PTQ)와 달리 학습 단계에서 양자화를 고려해, ~Q4 수준의 크기를 유지하면서 품질 저하가 더 적다. 멀티모달(이미지 입력)을 지원하고 128K context로 긴 문서 처리에 유리하다. 한국어·영어·일반 질의를 두루 처리하는 만능형으로 선택.

## 검토했지만 설치하지 않은 후보

### `deepseek-r1:32b` — 추론 슬롯, 미설치(skip)

| 항목 | 값 |
|---|---|
| MMLU | 90.8 (구 MMLU 기준) |
| 시점 | 2025년 1월 |

- 2025년 당시 강력한 추론 모델이었으나 **시점이 오래됐다**(Jan 2025).
- over-thinking/장황함(verbosity) 문제 — 간단한 질문에도 과도하게 길게 사고.
- **결정**: 추론 슬롯을 별도 모델 없이 `qwen3.6:27b`의 thinking 모드로 흡수. AIME 2026 94.1 / GPQA-Diamond 87.8로 최신 추론 성능이 더 좋고, 모델 하나를 덜 둬도 돼 메모리 예산에도 유리.

### `exaone3.5:32b` — 한국어 슬롯, 미설치

- 한국어 **네이티브 표현력은 최고** 수준.
- 그러나 **context가 32K로 상한**이 낮고, 어려운 한국어 다단계 추론에 약하다.
- **결정**: 128K context와 추론/멀티모달을 갖춘 `gemma3:27b-it-qat`가 만능형으로 더 적합. 표현력 한 가지만으로 32K 상한을 감수하긴 어려웠다.

### EXAONE 4.0 — 한국어 슬롯, 미설치

- **커뮤니티 버전만 존재**하고 Ollama 공식 라이브러리 모델이 아니다.
- **결정**: 공식 배포가 아니라 신뢰성/유지보수 측면에서 제외.

### `llama4:scout` — 미설치 (메모리 초과)

- 총 109B MoE → Q4에서도 약 **60GB**가 필요.
- 48GB 통합 메모리에 **들어가지 않는다**(MoE라도 전체 파라미터가 메모리에 상주해야 함).
- **결정**: 하드웨어 한계로 불가.

### `glm-5.1` — 미설치 (로컬 실행 불가)

- **cloud-only 태그**로, 로컬 실행이 안 된다.
- **결정**: Ollama 로컬 구동 목적에 부합하지 않아 제외.
