# 로컬 LLM (Ollama) 구축 기록

MacBook Pro (Apple M4 Pro, 48GB)에서 Ollama로 로컬 LLM 환경을 구성한 작업의 학습/작업 기록.

## 목적

- 클라우드 API에 의존하지 않고 코딩·추론·한국어 작업을 로컬에서 처리한다.
- 어떤 모델을 왜 선택했는지, 어떤 후보를 왜 버렸는지 trade-off를 남긴다.
- 새 머신에서 동일 환경을 다시 구성할 때 처음부터 다시 고민하지 않는다.

## 하드웨어

| 항목 | 사양 |
|---|---|
| 모델 | MacBook Pro, Apple M4 Pro |
| CPU | 12코어 (성능 8 + 효율 4) |
| 메모리 | 48GB 통합 메모리(unified memory) |
| 메모리 대역폭 | 약 273 GB/s |
| OS | macOS (Darwin 25.5.0) |

> 📌 macOS는 통합 메모리의 약 70~75%(≈34~36GB)를 기본적으로 GPU에 할당한다. `sudo sysctl iogpu.wired_limit_mb`로 상향 조정 가능하다. MoE 모델이라도 **전체 파라미터가 모두 메모리에 상주**해야 하므로(활성 파라미터만 적은 것이지 로드량이 적은 것은 아님) 메모리 예산은 전체 파라미터 기준으로 계산해야 한다.

| 단계 | 상태 | 날짜 | 산출물 |
|---|---|---|---|
| 1. 환경 확인 (ollama client v0.24.0, daemon 미기동) | ✅ 완료 | 2026-05-24 | `ollama serve` 기동 |
| 2. 용도별 모델 선정 (리서치 에이전트 2개로 후보 분석) | ✅ 완료 | 2026-05-24 | 코딩 2종 + 한국어/일반 1종 결정 |
| 3. 모델 pull (3종) | ✅ 완료 | 2026-05-24 | 모델 디렉터리 ~50GB |
| 4. 구동 검증 (smoke test) | ✅ 완료 | 2026-05-24 | `qwen3-coder` "OK" 응답 ~6.5s, 100% GPU |
| 5. 튜닝 설정 (`iogpu.wired_limit_mb`, `OLLAMA_MAX_LOADED_MODELS`) | ⏳ 선택(후속) | - | 필요 시 적용 |

## 모델 선정 과정 요약

시작점은 3개의 용도 슬롯이었다:

1. **코딩** — 코드 작성/리뷰/설계/자료분석
2. **추론** — reasoning 중심 작업
3. **한국어 글쓰기·일반** — 주식·취미 등 일상 질의 포함

리서치 에이전트 2개가 M4 Pro 48GB 제약과 2026년 5월 기준 벤치마크에 대해 후보들을 분석했고, 최종 결정은 다음과 같다.

- **코딩 슬롯 → 2종 모두 설치.** 품질용 dense 모델 `qwen3.6:27b`(리뷰/설계)와 속도용 MoE 모델 `qwen3-coder:30b`(빠른 인터랙티브)를 역할을 나눠 함께 둔다.
- **추론 슬롯 → 별도 설치 안 함(skip).** `deepseek-r1`을 검토했으나 `qwen3.6`의 thinking 모드로 흡수했다. deepseek-r1은 시점이 오래됐고(2025년 1월) over-thinking/장황함 문제가 있었다.
- **한국어 슬롯 → `gemma3:27b-it-qat` 선택.** 만능형 + 128K ctx. `exaone3.5:32b`(한국어 표현은 최고지만 32K ctx 상한, 어려운 한국어 추론 약함)와 EXAONE 4.0(커뮤니티 버전만 존재, 공식 라이브러리 아님)을 제쳤다.

상세 근거와 미설치 후보의 탈락 사유는 [02-models.md](02-models.md) 참고.

## 사용법 (한 줄 요약)

```bash
ollama run qwen3.6:27b                    # 코드리뷰·설계·자료분석 (thinking)
ollama run qwen3-coder:30b-a3b-q4_K_M     # 빠른 코딩
ollama run gemma3:27b-it-qat              # 한국어 글쓰기·일반
```
